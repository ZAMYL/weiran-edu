# 未然 EDU — 产品需求（V1.4 基准）

状态：**V1.4（2026-11-18）为当前产品与工程基线**，取代此前"六类分析"口径与 `docs/archive/` 下的 v0.1 草案。
本文是仓库内的口径摘要，详细论述以 V1.4 总文档为准；两者冲突时以总文档为准，并回头修正本文。

## 1. 目标与用户

- **目标用户**：程序设计竞赛、编程测评与教学研究中的教师、评测组织者和研究人员。
- **分析对象**：程序代码、题目、测试点表现、已有评分记录及相关资料；按本次测评建立分析批次。
- **产品产出**：五维能力分析、群体错误模式、个人证据、AI 解释，以及教师可保存和导出的诊断报告。
- **一句话**：从编程表现中发现能力差异，并让每个结论都能回到原始代码与测试记录。

## 2. 用户主流程

上传资料 → 系统自动识别结构与内容 → 结构化提取入库 → 五维分析与典型错误模式 → 从群体发现下钻到个人与代码证据 → 真实 Qwen Agent 调查 → 教师核查 → 保存并导出报告。

文件类型、学校、课程和模板等技术选择尽量由系统自动完成，不要求教师先选模板。

## 4. 五维与错误模式

五维固定为：算法与数据结构、代码实现能力、问题建模能力、效率意识、解题策略。

- 有原始评分时显示评分与来源；有代码与评测结果时显示已提炼的特征、错误模式与证据。
- **每次上传按实际资料生成本次分析内容，不补空卡片、不给默认分数。**

错误模式的分析链路：先由确定性程序聚合测试现象（通过/错误/超时/资源消耗），再抽取可定位的代码结构特征，最后交由 Qwen 结合题目要求解释失分原因与知识点关联。

## 5. 真实 Qwen Agent 的验收条件（硬性）

必须在网页上触发一次完整调查，且同时满足：

1. 服务端发出**真实网络请求**并收到提供商返回；
2. 模型**至少调用一个本地分析工具**，并用工具结果形成最终回答；
3. 后台保存请求时间、模型、执行来源、请求与费用统计；
4. 浏览器能展示同一批次的分析与证据；
5. 离线 Mock 仅用于自动化测试，**不作为真实能力证据**。

## 6. 数据与隐私口径（与旧草案相反，以本节为准）

- 系统读取上传文件中实际保存的姓名、学号及其他字段，并在教师工作台和报告中**按原值展示**；不自行改名，也不把学号替换成随机编号。
- `participant_id` 等内部键只用于数据库关联，不作为对外身份。
- 上传前完成脱敏与使用授权由**上传人**负责；平台不代替上传人做合规判断。
- 完整源文件与代码在本地服务端处理；发送给远程模型的是执行调查所需的统计结果和特征摘要。
- 与上述不冲突、继续有效的红线：真实学生数据、原始文件、数据库与密钥**不得提交到 Git**；密钥只在服务端读取。

## 7. 证据模型（逻辑模型）

`SourceAsset`（文件与哈希）、`Assessment / Problem`（测评与题目）、`Participant`（内部键 + 原值姓名学号）、`Submission`（学生 × 题目 × 语言 × 代码）、`TestObservation`（测试点状态、耗时、内存）、`CodeFeature`（可查询代码特征）、`Finding / EvidenceRef`（五维结果与错误发现的来源引用）。

`EvidenceRef.locator.kind` 允许：`html-node`、`test-case`、`code-span`。

## 8. 非目标（本轮不做）

- 代码执行沙箱（只保留扩展接口）。
- 通用 PDF / 图片 OCR。
- 全校多租户与学校 SSO。
- 虚构成长曲线、自动评分或学生排名。

## 9. P0 签收清单

- [ ] 可直接上传真实编程测评资料，系统自动识别结构与内容。
- [ ] 题目、代码、测试点、已有评分与来源能正确提取并关联。
- [ ] 五维分析与群体错误模式显示当前实际数据。
- [ ] 从群体记录能进入个人详情，姓名和学号与源文件一致。
- [ ] 真实 Qwen 已接通，工具调查与结果回读在网页完成。
- [ ] 教师可以核查依据、保存并导出分析报告。
- [ ] 前后端和 AI 在同一提交版本完成端到端验收。
