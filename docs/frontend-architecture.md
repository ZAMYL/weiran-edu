# 未然 EDU 前端技术与组件规范

日期：2026-10-24。先完成设计阅读与技术决策，再开始实现。

集成说明：最初的独立本地版本使用 Vite。收到正式仓库后核对已有工程，本次交付沿用 `apps/web` 的 Next.js 16 App Router、TypeScript 5.9 和现有 CI；不向仓库引入第二套应用构建器或路由框架。以下规范以本次仓库版本为准。

## 设计依据与产品范围

以 `design/edu-suite/README.md`、`screens.json` 和其中十张选用图片为实施依据。学生详情、画像全屏、测评全屏使用 `-v2` 稿；`design/concepts` 是方向探索资料，不混用其他主题。

三个业务入口：学情洞察、画像探索、测评数据。首版采用本地演示模式，支持真实 Excel 文件在浏览器解析和校验；未接入服务端、账号权限、数据库或 AI 模型。教学分析明确标为规则模板，不能显示为真实 AI 已生成。已确认批次仅存于当前浏览器会话内存，刷新恢复初始演示数据。

## 技术决策

| 层     | 选型                                 | 理由                                                                  |
| ------ | ------------------------------------ | --------------------------------------------------------------------- |
| 基础   | React 19 + TypeScript strict         | 复用筛选器、抽屉与图表，静态检查领域数据                              |
| 构建   | Next.js 16 App Router + pnpm         | 沿用现有工程和构建检查；交互由客户端组件实现                          |
| 组件库 | Ant Design 6 + Ant Design Icons      | 表格、分页、选择器、上传、抽屉、消息和空状态统一交互                  |
| 路由   | Next.js 文件路由 + Link              | 三个主入口，共用路由组 layout 保留跨页工作台状态                      |
| 状态   | Zustand 5                            | 当前批次、已应用条件、跨页分析对象；草稿筛选留在页面局部              |
| 图表   | Apache ECharts 6，按需注册           | 雷达与分布图，ResizeObserver 适配抽屉和全屏；热力图用语义化可点击矩阵 |
| Excel  | read-excel-file 9                    | 浏览器解析 xlsx，保留工作表、原始单元格和行号                         |
| 样式   | CSS 变量 + 页面/组件作用域类         | 统一 token，不额外引入另一套 UI 或 utility 框架                       |
| 验证   | TypeScript + Vitest + 浏览器流程检查 | 重点验证统计一致性、筛选和导入阻断；不为静态布局堆测试                |

运行环境沿用仓库：Node 24、pnpm 11.25.0。依赖的实际版本以 `apps/web/package.json` 和 `apps/web/pnpm-lock.yaml` 为准。增加的依赖仅限前端，不修改后端锁文件、CI、API、数据库或分析模块。Ant Design 通过 `@ant-design/nextjs-registry` 收集首屏样式。

## 视觉规范

- 主色 `#2463F5`，页面背景 `#F2F6FE`，深蓝文字，白色卡片。
- 卡片圆角 14px；桌面内容间隔 24px、页边距 32px；常规顶部导航 72px，全屏顶部 64px。窄屏逐级改为单列，表格局部横向滚动。
- 字体使用本地中文系统字体，无远程字体依赖；正文 14–16px，标题 28–32px。
- 顶部品牌与胶囊导航，不加入侧栏；主按钮每个任务区保持清晰优先级。
- 成功、待验证、错误均用文字和图标表达；禁止仅靠颜色传递状态。
- 所有原生交互有焦点样式，图表提供可读数据描述；抽屉使用组件库焦点管理。

## 组件边界

- `AppShell`：品牌、导航、批次选择、帮助、全屏；全屏隐藏全局导航并保留当前业务状态，Esc 退出。
- `PageHeading`、`Panel`、`StatCards`、`StatusTag`：共享页面结构，禁止页面重复定义相同 token。
- `AbilityChart`：注册 ECharts 所需模块、观察容器变化、卸载销毁。
- `FilterBuilder`：编辑草稿条件；只有“应用筛选”更新群体。重置清空所有条件。
- `StudentTable`：统一匿名标识、五维评分、分页、选中行和详情入口。
- `EvidenceDrawer`、`StudentDrawer`、`AnalysisDrawer`：共用同批次与同分析对象；原始记录可追溯。
- `ImportPreview`：原值只读、质量报告、定位错误；有阻断问题时无法确认。

## 数据与业务规则

- 领域模型集中在 `src/domain`；页面不自行计算另一套统计。全批次与群体均由同一 records 派生。
- 五个维度的编码、名称、最小值、最大值和步长来自批次评价标准。演示标准为 1–5 整数，不从图片数值反推正式标准。
- 演示热力矩阵共 105 人，默认“解题策略 ≥ 4 且算法与数据结构 < 3”恰好 21 人；均值按实际演示记录计算，不硬编码图上的均值。
- 原始评分保留 unknown 原值，校验通过才进入规范记录。缺失、越界、非数值、重复学生维度、未知维度、评语缺失等阻断确认，不自动修复。
- Excel 首版支持明确的长表格式，首行列名为“学生标识、能力维度、原始评分、原始评语”。能力维度使用五维全称。每名学生每维一条记录；支持多个工作表，记录真实工作表名、行号和列标识。任一非空工作表格式不符即阻断，不静默跳过。
- 导入预览必须选定评价标准；首版只提供明确标注的演示 1–5 标准。真实标准未提供时应先补充，不能把演示标准称为正式标准。
- 同一文件以 SHA-256 检查重复；重命名不绕过检查。确认创建独立批次，不覆盖当前批次。
- 统计事实、示例评语、可能解释和教学建议分区。统计核验表示本地算式一致，不代表真实测评已核验。
- 不根据截图虚构用户信息、评分标准版本、第二个已导入批次、AI 请求或提升幅度。

## 目录及代码约定

以下路径均相对于 `apps/web`：`src/app` 放 Next.js 路由、主题、状态和壳；`src/components` 放共享 UI；`src/features` 按 insights/explorer/assessments 分业务；`src/domain` 放演示用的纯类型、筛选统计和导入校验；`src/demo` 放显式合成记录；`src/services` 放文件解析适配。页面不直接访问未来 API。

评分阈值、长表列名与计算均是客户端演示约定，不是公共接口契约，也不替代 `apps/api` 已有的分析规则草案。正式导入、校验和统计应在与相关负责人确认后接入服务端。没有读取、修改后端的业务规则。

合成 Excel 由 `scripts/generate-import-samples.mjs` 在开发、构建和测试前生成，不提交二进制文件；真实 Excel/CSV、依赖、构建目录、测试截图及环境文件保持忽略。设计图片均为合成 UI 稿，图片中的文件名、学生编号和评语是示意资料。

组件 PascalCase，hook 使用 use 前缀，领域编码用稳定英文 key、界面文案中文。禁止 any、禁止吞掉错误、禁止用随机数制造统计。后续接入后端时通过 service 层替换演示来源，再按真实接口引入服务端缓存；本期不预装无调用场景的请求框架。
