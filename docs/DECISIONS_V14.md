### 1.2 谱系隔离

`D:\AI\传智杯\web后端\apps\api\app\models\migrations` 是旧沙盘产品线的独立谱系（`002_case_deletion`、`003_condition_extractions`、`004_card_version_snapshots`、`005_strategy_generation`、`006_strategy_details`、`007_dynamic_strategies`）。

- 两套谱系**禁止混用**：同为 `002`、`005`、`006` 的文件名与内容完全不同，混入即撞号。
- 旧沙盘「条件卡」方案（`cases` / `condition_cards`）**作废，不占号、不入库**，不作为 V1.4 交付内容。

### 1.3 发号流程

1. **先占号再写**：在 Issue 或 PR 里写明「申请 00X，内容一句话，负责人，预计合入时间」，同一编号只允许一个在途占用。
2. **一支一号、一号一责**：一个迁移只做一类改动（建表 / 加索引 / 加约束），不把无关表塞进同一文件。
3. **只向前**：已合入 main 的迁移不得就地修改；需要变更时新增下一号迁移，并在说明里写清原因。
4. **命名**：`NNN_<英文小写下划线主题>.sql`，主题与表名对应，不使用中文文件名。
5. **建表约定**：沿用现有风格——`STRICT` 表、字段级 `CHECK`（长度、枚举、非负）、`TEXT` 存时间、外键显式 `REFERENCES`、索引命名 `<表名>_<用途>`。
6. **同步交付**：新增迁移必须同 PR 带最小测试（建表成功、约束生效、重复/越权场景被拒），否则不合入。

## 二、数据出境边界（本地存储 / 前端展示 / 远端模型三层分开）

结论：**原文留在本地，教师看得到；发给远端 Qwen 的只有特征与统计，且用别名替换身份。**

### 2.1 三层模型

| 层 | 允许内容 | 说明 |
| --- | --- | --- |
| 本地存储（SQLite） | 姓名、考号/学号、代码全文、测试点、得分、来源路径、文件摘要 | 证据源必须完整；18.1 签收要求「姓名学号与源文件一致」，不存原文无法回看 |
| 前端展示（教师端） | 同上传文件原值，仅限有权限的教师与Owner范围 | 07.1 明确要求原样展示，系统不改名、不把学号换随机号 |
| 出境（远端 Qwen） | 特征、统计、题目结构；身份用别名 | 07.1「只接收必要的已处理统计和特征」 |

### 2.2 出境字段白名单

请求远端模型时，payload 必须由显式字段清单构造。禁止 `dict(row)`、`SELECT *`、整行序列化后直传。

| 字段 | 类型 | 是否出境 | 约束 |
| --- | --- | --- | --- |
| 题目编号 / 序号 | 结构 | 允许 | 用题目 `label`，不带内部主键 |
| 题面文本 | 文本 | 允许（须处理） | 先过 `edu/privacy.py` 的 `redact_text`；出现人名、联系方式替换为 `[已脱敏]` |
| verdict 分布（AC/WA/TLE/MLE/RE…） | 统计 | 允许 | 每个分组人数须满足 2.3 |
| 得分分布、平均分、满分/零分人数 | 统计 | 允许 | 同上；不附个人明细 |
| 测试点失败分布、耗时/内存分档 | 统计 | 允许 | 同上；仅分档，不给绝对耗时明细与学生标识 |
| 代码结构特征（循环嵌套深度、是否递归、索引访问模式、数据结构使用） | 特征 | 允许 | 只发结构化特征，不发代码文本 |
| 身份别名 `p01…` | 标识 | 允许 | 2.4 的本地别名，不含姓名或考号 |
| 姓名 `display_name` | 身份 | **禁止** | 任何形式（含拼音、缩写、脱敏后仍可识别的片段） |
| 学号 / 考号 `external_key` | 身份 | **禁止** | 同上 |
| 代码原文 `code_text` | 原文 | **禁止**（默认） | 例外见 2.6 |
| 原始 HTML / 原始文件内容 / 文件路径 | 原文 | **禁止** | 仅本地留存 |
| URL、邮箱、手机号、12–18 位数字串 | 联系信息 | **禁止** | `privacy.py` 的 `CONTACT` 兜底替换 |
| 文件 SHA-256 | 摘要 | 按需 | 仅用于任务去重与审计，不进入提示词正文 |

### 2.3 小样本不下发

群体统计下发前，沿用 `app/ai/edu/discovery/disclosure.py` 的 `check_disclosure`：

- `minimum_cell` 默认 **5**（`app/ai/edu/discovery/models.py` 的 `Limits`），任一分组人数小于该值即抛 `privacy_limited`，不发送。
- 同时检查与已释放/待释放集合的差分，防止两次请求逐步逼近单个个体。
- 拒绝时任务状态记为 `privacy_limited`，前端按现有方式提示数据不足，不用模型编造结论填补。

### 2.4 身份别名

- 出境用 `p01`、`p02`…，本地维护 `alias → student_pk` 映射，仅存服务端内存/任务记录，不写进模型提示词之外。
- 模型返回结果入库与前端展示前，用映射换回 `display_name` 与 `external_key`，保证「界面显示的仍是上传文件里的原值」。
- 别名按批次重新生成，不复用上一批次的别名，避免跨批次关联。

### 2.5 回程过滤

模型返回的标题、解释、建议文本入库前必须过 `edu/privacy.py` 的 `checked_text`（或等价的 `redact_text` 校验），命中身份词或联系方式即拒绝写入，防止模型从上下文猜出或回显姓名、学号。

### 2.6 代码片段的例外开关

若后续确需模型理解具体实现，走显式开关，默认关闭：

| 项 | 规则 |
| --- | --- |
| 开关 | `AI_SEND_CODE_SPANS`，默认 `false` |
| 开启后单次上限 | 每次任务最多 3 条片段，单条不超过 5 行、不超过 400 字符 |
| 处理 | 发送前必须过 `redact_text`；注释中的姓名、学号、URL 一并替换 |
| 记录 | 任务记录写入 `code_spans_sent` 计数与片段哈希，便于事后审计 |
| 关闭时行为 | payload 中只有结构特征，模型不得要求原文，后端直接拒绝该请求 |

### 2.7 审计字段（10.2 验收所需）

每次真实调用必须落一条任务记录，至少包含：

- `origin`（`qwen_live` / `http_mock`）、模型名、请求时间、耗时
- 请求数与 token 用量、费用估算
- `sent_fields`（字段名清单，不存字段内容）、`alias_count`、`k_anonymity_result`、`prompt_bytes`
- 工具调用记录与来源引用（`evidence_refs`）
- 失败原因码（含 `privacy_limited`、`AI_LIVE_NOT_ENABLED`）

`sent_fields` 只列字段名，用于复核「发出去的是什么类型的数据」，不保存原文快照。

### 2.8 与既有文档的口径差异

`docs/V1_FILE_INTAKE.md` 曾写「正式数据不进入 Qwen」。V1.4 起细化为：

- **原文（姓名、学号/考号、代码、原始文件）不进入 Qwen**，与本文件 2.2 一致；
- **统计与特征摘要可以进入**，这是 10 节「真实 Qwen Agent」的前置条件。

历史文档不修改，本文件作为增量口径，冲突时以本文件为准。

### 2.9 明确不做

- 不在服务端自动改名、不把学号替换为随机编号（07.1 禁止）；脱敏责任在上传方，系统只做出境裁剪。
- 不为同一能力建第二套接口；出境构造复用现有任务服务与工具层。
- 不在日志、异常信息、前端错误提示中输出姓名、学号或代码原文。
