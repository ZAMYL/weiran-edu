审查日期：2026-10-25。基线：`12dd7f9d5693c379c99cc6ccbcf326921b03dd40`。

## 发现与修复

1. **匿名学生引用未冻结。** 原有不可变触发器覆盖评分、批次、标准和身份表，但未覆盖 `students`。数据库写入者可修改 `public_id`，使同一 `snapshot_id` 返回不同的学生引用。追加 `003_immutable_students.sql`，拒绝更新和删除学生引用；修订仍追加新批次。
2. **分页事实校验范围不一致。** 在隔离测试库模拟第二个学生评分缺失、来源哈希不一致或来源单元格错位时，第一页学生查询仍可返回成功。现于授权后的同一只读事务内校验完整批次的成员范围、五维数量、评分区间、标准来源和证据坐标；学生分页、统计、群体筛选、单条证据、学生证据和标准查询统一失败为 `503 DATA_INTEGRITY_ERROR`，包括越界空页。

这两项是存储一致性防护缺口，没有复现普通 HTTP 调用者借此越权写入。原有评分标准版本已具备不可变保护，无需重复迁移。

## 权限与隐私边界

- 当前教师及凭证复核仍先于批次授权；未授权批次返回通用 `404`，错误快照对有权教师返回 `409`，凭证撤销返回 `401`。
- 完整性检查不查询原始身份、评语正文、标准正文或 Excel 二进制；SQLite authorizer 回归测试直接禁止读取这些列。
- 错误继续使用统一结构、服务端 `X-Request-ID` 与 `Cache-Control: no-store`。
- 本次校验覆盖存储元数据关系，不重新解析原始工作簿；持有数据库管理权限者仍可删除触发器或一致地伪造事实，不应将触发器描述为对数据库管理员的安全隔离。

## 接口与升级影响

HTTP 路径、请求/响应字段、维度映射和 `Fraction` 转换保持原契约。读取新增一次完整批次的元数据校验，成本随学生数线性增长；不扫描私有正文。批次列表和批次元信息接口未增加事实扫描。

迁移须由运维显式执行，HTTP 不自动迁移。先备份目标数据库，再在已更新代码的 `apps/api` 下执行：

```powershell
uv run --locked python -m app.edu --database 'D:\private-runtime\edu.sqlite3' init
```

示例路径须替换为仓库外的实际数据库。迁移不重写历史数据；已应用的 `001`、`002` 文件及校验和保持原样。新建库和已有两次迁移的数据库均有回归验证。完成迁移后重启后端。
