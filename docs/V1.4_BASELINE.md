# V1.4 基准（生效：2026-11-18）

> 本文是**口径裁决书**：出现矛盾时以这里为准。
> 产品需求的完整表述见 [PRD](PRD.md)，架构与证据模型见 [ARCHITECTURE](ARCHITECTURE.md)。

## 1. 适用范围

V1.4（2026-11-18）为当前唯一的**产品与工程基线**，取代此前"六类分析"口径以及 `docs/archive/` 下的 v0.1 契约。
本文件不描述实现细节，只裁决"哪套口径有效"。

## 2. 五条关键口径

| 主题 | 现行口径 | 已废止 |
| --- | --- | --- |
| 身份与显示 | 姓名、学号按上传资料**原值展示**；`participant_id` 仅作内部关联键；脱敏与授权由上传人负责 | 匿名 ID 强制替代学号；普通接口一律不返回真实姓名 |
| 资料接入 | 单文件 / 多文件 / ZIP 统一入口，先识别内容再分发适配器 | 只接受固定双 Sheet 模板 |
| 分析口径 | 五维能力 + 典型错误模式 + 群体/个人证据 | 六类确定性分析作为产品主线 |
| AI 能力 | 真实 Qwen：真实请求 + 至少调用一个本地工具 + 记录来源与费用 + 网页可回读；Mock 仅用于自动化测试 | AI 四段式教学解释；以合成通道代表真实能力 |
| 证据模型 | `SourceAsset / Problem / Participant / Submission / TestObservation / CodeFeature / Finding+EvidenceRef` | 仅有评分与评语证据 |

## 3. 仍然有效的红线

- 真实学生数据、原始文件、数据库、密钥**不得提交到 Git**。展示 ≠ 入库。
- 密钥只在服务端读取，不得进入客户端或仓库。
- 确定性程序负责计数、分数与筛选；模型只做调查与解释，不得回写事实。
- 未测试要写明原因，不得把 Mock 结果当作真实模型验收。

## 4. 文档效力顺序

1. 本文件（口径裁决）；
2. [PRD](PRD.md)（需求）；
3. [ARCHITECTURE](ARCHITECTURE.md)（架构与证据模型）；
4. 仍描述**当前实现**的专题文档：[DATABASE_BATCH_AUTH](DATABASE_BATCH_AUTH.md)、[STATISTICS_GROUP_EVIDENCE_API](STATISTICS_GROUP_EVIDENCE_API.md)、[EXCEL_PARSER](EXCEL_PARSER.md) 等；
5. `docs/archive/**`：历史记录，**不再具有约束力**。

## 5. 冲突处理

- 专题文档与 V1.4 冲突时，以 V1.4 为准，并在该文档顶部保留"已被 V1.4 取代"的提示。
- 需要推翻 V1.4 的改动，必须由项目负责人 ZAMYL 明确批准，并在 PR 中写明影响范围。
- 新增需求先说明：对应用户流程、复用模块、实际输入、验收结果，再分配负责人。
