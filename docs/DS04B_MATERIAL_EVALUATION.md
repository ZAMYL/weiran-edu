## 数据与评测口径

[`cases.json`](../evals/material_semantics/cases.json) 有 9 组手工构造的抽取后资料和人工方式编写的标注：
3 组开发、6 组保留；覆盖编程答卷、五维/其他维度评价、表格重排、跨文件键、重复/缺失、
无表头、抽取不完整、无可用表结构，以及恶意表头和单元格。
`null` 是刻意不判，不等于漏标。关联标注区分“值得提出的键”和“不能确认的关联”。
已逐案按合成来源设计核对，测试验证标注覆盖所有表和字段引用；没有第二人独立复标。
这不是模型训练语料，也不证明已验证真实文件解析或泛化。公开保留集适于重复核验，正式质量评审可再加私有合成盲测集。

- **规则层**：少量确切字段线索、同表字段组合和键唯一性候选，仅消费和 AI 相同的安全概要。
  没有名字、单元格、标准答案或权限；不把原有验证器误作语义识别器。
- **模型层**：`evaluate_model` 经 `understand_materials` 接收外部准入的 sender。
  按表角色、列语义、关联端点与基数计 TP/FP/FN、micro 查准/查全率；角色和字段另计精确命中率。
  标准未知项单独报告弃答；格式错误、无效引用、无依据建议及漏报分别记录。
  无效引用的可解码候选仍纳入建议层分母，但不会产生安全结果；
  格式错误计为该例未找回任何标注。没有候选时比例为 null。不会输出原始模型响应。
- **验证层**：同一候选跑 DS-04A 验证，保留状态、关联待确认和无授权可用项；
  独立的本地反事实测试验证可信字段和同一身份域才能确认。真实模型测量不注入
  `TableAuthority` 或金标。MockTransport 只验现有 `post_chat` 协议及指标采集，
  `protocol_only` 报告不生成模型效果分数。

## 实测与最小修正

基线会把未命中词表的整条表头清空（例如“实得分”、`OJ Verdict`）。
只补 5 个确切同义词，将其映射到已有受控提示词，不外发任意陌生原表头，
不新增学校/文件/位置分支。恶意后缀不匹配。此变更会让某些字段从待确认变为
类型相容的候选，但不会确认语义或放开任何权限。

| 同一规则比较 | 改前 | 改后 |
| --- | --- | --- |
| 全集已标注字段找回 | 28/37，查准率 100% | 33/37，查准率 100% |
| 已知角色精确命中 | 7/9 | 8/9 |
| 标注字段没有表头线索 | 9 | 4 |
| 保留集已标注字段找回 | 13/17 | 13/17 |
| 关联键候选查准/查全 | 1/2、1/2 | 1/2、1/2 |
| 应弃答项 | 11/11 未猜测 | 11/11 未猜测 |

这只是规则/线索改进，**不是模型效果提升**。漏掉的 4 个字段仍集中在保留的陌生学校命名。
规则用唯一的一侧反向猜多对一，无法识别另一侧重复与缺键的实际业务身份关系：
原候选不被验证为可信关联，结果要求确认。恶意表头/单元格不会进入提示；
构造的“分数是学生键”猜测虽然类型相容，仍未获得确认或解锁分析。
不存在的列和重复 JSON 键分别被拒绝。实际模型错误病例待准入后测，不能从这些反例推断。

## 复跑及预算

在仓库根目录运行，使用 API 的已锁定 Python 环境，并将 `apps/api` 加入 `PYTHONPATH`：

```powershell
$env:PYTHONPATH=(Resolve-Path apps/api).Path
uv run --project apps/api python -m evals.material_semantics rules --split all
uv run --project apps/api python -m evals.material_semantics compare-headers
uv run --project apps/api python -m evals.material_semantics budget --case contest_standard --case five_dimensions --case opaque_school_holdout
```

目录内有真实运行的 [规则结果](../evals/material_semantics/rules_result.json)
和[表头对比](../evals/material_semantics/header_comparison.json)。
budget 命令在本地输出合成集和每个拟发送 payload 的 SHA-256，不发送请求。
拟议三次调用 `qwen3.8-flash` 北京同步非思考，每次输出最多 800 token。
按现有准入账本保守口径（每次预留 991,808 输入 token）总预留
2,977,824 token，历史快照上界 ¥2.3868192，**不是实付金额或目前有效报价**。
仓库参考价格有效至 2026-11-19 UTC；实际执行日应独立复核官方价格、区域、模型和有效期。
